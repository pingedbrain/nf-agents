# lineage-fixtures Specification

## Purpose

Committed, offline, reproducible Nextflow lineage stores plus the `nextflow lineage` CLI output
(the oracle) for every supported Nextflow format generation, so that `baqueano-lineage` and
`baqueano-mcp` can be tested from a plain git checkout with no Docker, network, cards or keys.
Generation needs only bash and Docker.

Terms: **version dir** = `fixtures/lineage/<name>/`; **recorded root** = `/nf-agents-fixture`
(the absolute path the generated tree had inside the container); **data file** = a file whose
absolute path is the `path` of a `FileOutput` record; **core matrix** = `25.04.8`, `25.10.9`,
`26.04.9`, `26.10.7`.

## Verification checks

| ID | Kind | Command / name |
|----|------|----------------|
| P-* | python unittest (offline) | `python3 -I -m unittest discover -s scripts/fixtures -p 'test_*.py'`; test names below are `test_fixtures.<Class>.<method>` |
| F-check | offline check (CI `test`) | `python3 -I scripts/fixtures/check.py fixtures/lineage` |
| G-gen | generation (Docker) | `scripts/gen-fixtures.sh` (all core versions + agent store) |
| G-verify | round trip (Docker) | `scripts/gen-fixtures.sh --verify` (committed fixtures only, no regeneration) |
| G-shape | determinism (Docker) | run G-gen twice; `git diff --exit-code -- 'fixtures/lineage/*/shape.txt'` |
| G-edge | generation (Docker) | `scripts/gen-fixtures.sh --out "$(mktemp -d)" 26.11.0-edge` |
| V-* | verify (inspection) | grep / `git check-ignore` / `git check-attr` as stated |

## Requirements

### Requirement: Minimal pipeline

`fixtures/pipelines/minimal/` MUST contain `main.nf`, `nextflow.config` (`lineage.enabled = true`)
and synthetic `data/seed.txt`. `main.nf` MUST define exactly three processes chained
GENERATE → TRANSFORM → SUMMARIZE, a `greeting` param, and an `output` block that publishes one
file into a subdirectory and one file at the output root with a label. It MUST run unmodified on
25.10.9 … 26.10.7 and on 25.04.8 with only `nextflow.preview.output = true` prepended. It MUST
NOT need network access or any non-synthetic data.

#### Scenario: Every core version produces published outputs (G-gen, F-check)
- GIVEN the core matrix
- WHEN G-gen runs
- THEN each version dir holds a `WorkflowOutput` record and ≥ 2 published `FileOutput` records per run

#### Scenario: 25.04 preview flag (G-gen, V-preview)
- GIVEN version `25.04.8`
- WHEN the pipeline is staged
- THEN only the staged copy starts with `nextflow.preview.output = true`; the committed `main.nf` does not

### Requirement: Generator interface

`scripts/gen-fixtures.sh [--verify] [--out DIR] [VERSION…]` MUST require only bash and Docker
on the host, default to the core matrix and `fixtures/lineage`, and accept tags matching
`^[0-9]+\.[0-9]+\.[0-9]+(-edge)?$`. It MUST exit non-zero with a message naming the cause when
Docker is unavailable, a tag is invalid or cannot be pulled, any run or capture step fails, or
verification fails. It MUST NOT write outside `--out` and its temporary directory, and MUST
replace a version dir only after that version's generation and round trip succeeded.

#### Scenario: No Docker (V-nodocker)
- GIVEN `docker` is not on `PATH`
- WHEN the script runs
- THEN it exits non-zero printing `docker not found` and writes nothing

#### Scenario: Invalid tag (V-badtag)
- GIVEN argument `latest; rm -rf /`
- WHEN the script runs
- THEN it exits non-zero naming the tag before calling Docker

#### Scenario: Failure keeps old fixtures (V-atomic)
- GIVEN committed fixtures and a version whose run fails
- WHEN the script runs
- THEN that version dir is byte-identical to before and the exit code is non-zero

### Requirement: Machine-independent records

Generation MUST run with the tree mounted at the recorded root, `--cpus 2`, as the image's
default user, with `NXF_ANSI_LOG=false`. Nothing under `fixtures/` MUST contain a host absolute
path, host user name or host name.

#### Scenario: No host leakage (F-check, P `CheckTests.test_host_path_rejected`)
- GIVEN any file under `fixtures/lineage`
- WHEN F-check scans it
- THEN no match of `/home/`, `/Users/`, `C:\\`, `/runner/`, `/__w/` or `/github/workspace` is found (G-gen additionally rejects the literal `$HOME` unless it is `/` or `/root`); a planted `/home/x` fails the check, the bare word `runner` does not (P `CheckTests.test_host_path_shapes_only`)

> Deviation (2026-11-26, apply PR B): host leakage is matched by host-path shapes and the literal `$HOME` instead of a bare user-name substring, which false-positives on `"runner": "langchain4j"` in AgentRun records when generated by the `runner` user in CI. `/root` is exempt because it is the container's own home (`metadata.homeDir`).

#### Scenario: Pool size pinned (F-check)
- GIVEN any `WorkflowRun` record
- THEN `config.poolSize` is `2`

### Requirement: Version dir layout

A version dir MUST contain: `.lineage/` exactly as Nextflow wrote it; every data file, as a
regular file at its path relative to the recorded root; `nextflow.config`; `oracle/`;
`manifest.json`; `shape.txt`. It MUST NOT contain symlinks, files under `work/` that are not
data files, `.nextflow*`, run logs or HTML.

#### Scenario: Published outputs dereferenced (F-check, P `ExportTests.test_symlink_dereferenced`)
- GIVEN a published file that was a symlink into `work/`
- WHEN exported
- THEN it is a regular file with the target's bytes and mtime

#### Scenario: Work pruned (P `ExportTests.test_only_data_files_kept`)
- GIVEN a task dir with `.command.sh`, `.exitcode` and an output
- WHEN exported
- THEN only the output referenced by a `FileOutput` remains

#### Scenario: Missing data file (P `ExportTests.test_missing_data_file_fails`)
- GIVEN a `FileOutput` whose path does not exist
- WHEN exported
- THEN export exits non-zero naming the LID and path

### Requirement: mtime manifest

`manifest.json` MUST be a JSON object with `format` (`1`), `kind` (`core` | `agent`),
`nextflow_version`, `image` (tag and digest), `recorded_root`, `store` (`.lineage`), and `files`: an array sorted by `path`, one
entry per data file and no others, each `{path, size, mtime_ms, sha256}` where `path` is relative
to the version dir (no `..`, no leading `/`), `mtime_ms` = floor(mtime ns / 10⁶) at generation.
Restoring every `mtime_ms` on a copy of the version dir mounted at the recorded root MUST make
`nextflow lineage check` succeed for every `FileOutput`.

#### Scenario: Manifest matches files (F-check, P `CheckTests.test_size_mismatch_fails`, `test_sha_mismatch_fails`)
- GIVEN a version dir
- THEN each entry's size and sha256 match the file; a one-byte change fails F-check naming the path

#### Scenario: Coverage (P `CheckTests.test_unlisted_fileoutput_fails`, `test_extra_entry_fails`)
- GIVEN the `FileOutput` paths under the recorded root
- THEN they equal the manifest paths as a set; any difference fails

#### Scenario: Path traversal (P `CheckTests.test_traversal_rejected`)
- GIVEN an entry `../../etc/passwd` or `/etc/passwd`
- THEN F-check fails without reading it

#### Scenario: Round trip (G-verify)
- GIVEN committed fixtures checked out by git (mtimes lost)
- WHEN G-verify restores `mtime_ms` on a temp copy and runs `nextflow lineage check` on every `FileOutput` LID
- THEN every output is `Checksum validation succeed`, exit 0, and `list` stdout equals `oracle/list.out`

#### Scenario: Without restore (G-verify)
- GIVEN the same copy without restored mtimes
- THEN `check` of a published `FileOutput` exits 1 (proves the manifest is load-bearing)

### Requirement: CLI oracle

`oracle/` MUST hold, per case, `<case>.args` (JSON array of the argv after `nextflow`),
`<case>.out`, `<case>.err` (byte-exact) and `<case>.exit` (decimal + newline), plus `ids.json`
mapping `RUN1`, `RUN2`, `TASK_<PROCESS>_RUN<n>` to LIDs. Core cases: `version`, `help`, `list`,
`view-workflowrun`, `view-workflowrun-output`, `view-published-file`, `view-published-file-subdir`,
`view-taskrun`, `view-taskrun-summarize`, `view-taskoutput`, `view-task-fileoutput`, `view-field`,
`view-not-lid`, `view-missing`, `find-taskrun`, `find-workflowrun`, `find-fileoutput`,
`find-fileoutput-label`, `find-taskoutput`, `find-workflowoutput`, `find-bad-field`, `find-noeq`,
`diff-runs`, `diff-tasks`, `check-published`, `check-taskfile`, `check-taskrun`, `check-tampered`,
`check-mtime-only`, `render-file`, `render-run`. Tamper cases MUST run on a disposable copy.
Every argv element MUST match `^[A-Za-z0-9:/#=._-]+$`.

#### Scenario: Complete case set (F-check, P `CheckTests.test_missing_case_file_fails`)
- GIVEN a core version dir
- THEN all cases have the four files and `.exit` parses as an integer

#### Scenario: Tamper isolated (F-check, G-verify)
- GIVEN `check-tampered.exit` = 1
- THEN committed data files still match the manifest and pass G-verify

#### Scenario: Unsafe argv (P `CasesTests.test_unsafe_arg_rejected`)
- GIVEN an argv element containing a space or quote
- THEN capture aborts before running Nextflow

### Requirement: Shape fingerprint

`shape.txt` MUST be a deterministic text summary: per record kind, the sorted set of JSON field
paths with value types; store layout with hashes masked; per oracle case the exit code and
sha256 of stdout/stderr after masking LIDs/hex hashes, UUIDs, timestamps and run names,
collapsing spaces, and (for `find-*`) sorting lines. Regenerating with the same images MUST yield
an identical `shape.txt`.

#### Scenario: Stable across regenerations (G-shape, P `ShapeTests.test_volatile_tokens_masked`)
- GIVEN two generations with different session UUIDs, hashes, run names and times
- THEN `shape.txt` is identical

#### Scenario: Real drift detected (P `ShapeTests.test_new_field_changes_shape`, `test_find_order_ignored`)
- GIVEN a record gaining field `spec.foo`, or a `find` output in another order
- THEN the shape changes in the first case and not in the second

### Requirement: AgentRun store

`fixtures/lineage/26.10.7-agent/` MUST be generated with 26.10.7, runner `langchain4j`, plugin
`nf-agent@0.2.0`, `agent.baseUrl` pointing to a stdlib stub on `127.0.0.1` inside the same
container, no API key and no outbound LLM traffic. It MUST contain ≥ 2 `AgentRun` records (one
with `tools`, one with a structured `outputSchema`) and follow the layout, manifest, oracle
(`version`, `list`, `find-agentrun`, `view-agentrun-<name>`, `view-agentrun-output-<name>`,
`render-agentrun`) and shape rules.

#### Scenario: Offline agent run (G-gen, P `StubTests.test_chat_completion_json_schema`)
- GIVEN no LLM credentials in the environment
- WHEN G-gen builds the agent store
- THEN `find-agentrun.out` lists ≥ 2 LIDs and the stub answers a `json_schema` request with schema-valid JSON

#### Scenario: Unsupported stub path (P `StubTests.test_unknown_path_501`)
- GIVEN `POST /v1/responses`
- THEN the stub answers 501 with a JSON error naming the path

### Requirement: Git hygiene and docs

`.gitignore` MUST NOT ignore files under `fixtures/lineage/*/work/`; `.gitattributes` MUST set
`-text` for `fixtures/lineage/**`. `fixtures/README.md` MUST state provenance (versions, image
digests source, generator command), that all data is synthetic, Apache-2.0 licensing, the mtime
manifest contract with a restore recipe, how to regenerate, and "never edit by hand".

#### Scenario: Work files tracked (V-ignore)
- GIVEN `fixtures/lineage/26.10.7/work/<xx>/<hash>/summary.txt`
- THEN `git check-ignore` exits 1

#### Scenario: No EOL conversion (V-attr)
- THEN `git check-attr text -- fixtures/lineage/26.10.7/oracle/list.out` reports `unset`

#### Scenario: README content (V-readme)
- THEN grep finds `Apache-2.0`, `synthetic`, `scripts/gen-fixtures.sh`, `mtime_ms`, `never edit`
